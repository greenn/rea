# Версионность проекта

Формат версии:

`0.MINOR.PATCH`

## Правила

- Первая цифра остаётся `0`, пока явно не принято решение перейти на `1.x`.
- `MINOR` — счётчик активных дней разработки.
- `PATCH` — счётчик пользовательских задач в пределах одного дня разработки.

### Новый день разработки

При первом изменении репозитория в новый календарный день:

- увеличить `MINOR` на `1`;
- сбросить `PATCH` в `1`.

Пример: `0.5.6` → `0.6.1`.

### Следующая задача в тот же день

Каждый следующий пользовательский набор изменений в тот же день увеличивает только `PATCH`.

Пример: `0.6.1` → `0.6.2` → `0.6.3`.

## Что считается одной версией

Один пользовательский запрос = один PATCH. Несколько связанных правок и файлов внутри одного запроса остаются одной версией.

## Когда версия не меняется

Версия не увеличивается при обсуждении, анализе, диагностике, исследовании и проверке состояния, если файлы репозитория не менялись.

## Дата

Для определения нового дня используется локальная календарная дата пользователя/проекта, а не UTC.

## VERSION.json

В корне проекта хранится `VERSION.json` с полями `version` и `lastChangeDate`. Публично отображаемая версия должна обновляться одновременно с ним.
